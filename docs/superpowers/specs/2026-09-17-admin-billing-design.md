# Creative 管理后台与双余额计费设计

## 目标

在保留现有订阅套餐、积分系统、生成任务队列和支付代码的前提下，增加单一超级管理员后台、动态套餐与模型定价、人民币预充值钱包，以及用户可配置的积分/余额支付策略。

## 核心规则

- 平台只有一个超级管理员；管理员身份保存在服务端配置中，普通工作区 Owner 不等于平台管理员。
- 用户设置主支付方式为积分或人民币余额，系统默认积分。
- 用户可开启自动切换；主余额不足时才尝试另一种余额。
- 单次生成只能使用一种余额全额支付，禁止积分与人民币组合扣款。
- 必须先成功扣费，再创建生成任务；余额不足时不调用服务商。
- 服务商返回有效图片、视频或明确内容安全拦截结果时不退款。
- 网络错误、接口错误、超时、空结果或异步任务最终无产出时原路退款。
- 所有扣款、退款、支付回调和管理员调账必须幂等并写入不可变流水。

## 管理后台

- `/admin`：经营概览。
- `/admin/providers`：复用现有生成服务商配置结构，管理 API 地址、加密密钥、启停状态。
- `/admin/models`：管理模型启停、积分价格、人民币价格、成本价和最低套餐。
- `/admin/plans`：管理套餐名称、说明、月价、年价、赠送积分和权益。
- `/admin/users`：查看用户余额与套餐并执行带审计记录的调账。
- `/admin/orders`：查看充值、订阅、支付回调与退款状态。
- `/admin/ledger`：查询积分和人民币流水。
- `/admin/settings`：管理积分单价、最低充值金额和支付渠道开关。

## 数据与安全

- 动态配置进入 Supabase；前端不再以硬编码价格作为计费依据。
- API 密钥只允许服务端读取，以应用级加密密文保存，后台仅显示掩码。
- 金额统一使用人民币分整数；积分使用整数，禁止浮点金额参与账务。
- 数据库 RPC 在行锁内完成扣款、退款和幂等检查。
- 管理 API 每次请求同时校验登录用户和超级管理员身份。

## 支付渠道

- 保留现有 Lemon Squeezy 订阅能力。
- 增加统一充值适配器，支持支付宝、微信支付和聚合支付实现。
- 没有商户号、证书或密钥时，渠道保持禁用，不提供虚假成功流程。
- 支付回调必须验签，并以渠道交易号作为幂等键入账人民币余额。

## 第一阶段交付

第一阶段提供完整的管理员配置与内部钱包闭环、管理员手工充值/调账、用户支付策略及生成扣款退款。官方支付与聚合支付提供真实适配器边界和配置校验；取得商户凭证后启用对应实现。

## 验收

- 超级管理员可以修改套餐、模型双价格和服务商配置。
- 用户可保存主支付方式与自动切换开关。
- 积分或人民币余额能够独立全额扣费，余额不足不创建任务。
- 自动切换仅在用户开启后生效，且不组合扣款。
- 可退款失败原路退款；有效产出和安全拦截不退款。
- 所有管理员修改、扣费、退款和充值可审计。
